# 前端 HCI 修正任务计划

## 1. 目标与范围

依据 [`docs/frontend-hci-review-yaorz-0904.md`](../frontend-hci-review-yaorz-0904.md)，按顺序修正以下问题：

- **第 1 大类：星图界面**，覆盖 `1.1`–`1.8` 全部条目。
- **第 2 大类：搜索界面**，覆盖 `2.1`–`2.8` 全部条目。
- 本轮**不处理第 3、4 大类**，也不扩展评审范围。

执行基线为当前已拉取并合并的 `main` 内容。实现必须保持现有功能、数据/API 契约、路由、视觉主题、字体、色板、间距和组件语义不变，只做完成评审项所需的最小调整。

## 2. 执行规则

1. 所有任务严格串行：前一项通过人工检查后，才开始下一项。
2. 每项任务完成后，先由执行者进行自检和视觉检查，再通知用户进行人工检查。
3. 人工检查未通过时，只修正该任务涉及的代码，不跨任务顺手重构。
4. 每次修改后记录文件、问题编号、验证结果和人工检查结论；不记录或暴露本地数据库密码等敏感信息。
5. 不改变后端接口和数据结构；若发现运行问题，只修复使现有前后端在当前 main 基线下正常工作的必要内容。

## 3. 任务分配与检查点

以下为逻辑角色分工；当前执行者按序承担并在每个检查点暂停等待用户确认。

### 任务 0：基线与运行确认

- **负责人**：主执行 / QA
- **目的**：确认当前 main 基线、前后端启动方式、关键页面入口和现有未改动行为。
- **范围**：不修改评审项代码；只建立运行基线。
- **自检**：前端生产构建；后端启动或健康检查；确认星图、搜索、下载队列入口可访问；记录已有工作区改动并避免覆盖。
- **人工检查点 0**：用户打开星图和搜索页面，确认当前页面可用、无本轮修改前的意外回归。
- **放行条件**：用户确认基线可用后进入任务 1。

### 任务 1：星图视觉层级与卡片布局

- **负责人**：视觉实现
- **问题**：`1.1` 数据集下拉菜单对比度；`1.5` 图谱控制菜单层级；`1.6` 反应关系卡下载按钮对齐；`1.7` 反应关系卡元素重叠。
- **实现边界**：沿用现有组件、图标、颜色变量和断点；仅调整必要的层级、对齐、间距、溢出和状态样式。
- **自检与视觉检查**：构建前端；在桌面宽屏和窄屏检查下拉菜单、控制菜单、反应关系卡；确认没有新增滚动条、布局跳动或遮挡；检查浏览器控制台无新增错误。
- **人工检查点 1**：
  - 打开 Dataset 菜单，确认文字与背景清晰可读，菜单不改变原有操作。
  - 打开 Graph controls，确认 `Clear Selection`、`Open Search Library` 与其他入口层级清楚且仍可用。
  - 展开反应关系卡，确认下载按钮位置统一、卡内标题/元信息/操作不重叠。
- **放行条件**：用户确认桌面和窄屏视觉无回归后进入任务 2。

### 任务 2：星图缩放、选择与拖拽交互

- **负责人**：交互实现
- **问题**：`1.2` 缩放方式与反馈；`1.3` 点击空白清除选择；`1.4` 横向拖拽位置与阻尼；`1.8` 拖拽闪烁。
- **实现边界**：保留现有节点、边、相机和选择模型；只补齐输入事件、视口边界、动画/拖拽状态和可见反馈，不更换图谱渲染方案。
- **自检与视觉检查**：验证滚轮/触控板仅在图谱区域缩放，页面其他区域仍可滚动；验证加减号、比例、重置（如现有 UI 入口）状态一致；连续拖拽多个节点并观察帧间是否闪烁、跳位或松手后漂移；检查空白点击清除高亮。
- **人工检查点 2**：
  - 在图谱上滚动、缩放、拖拽，并在图谱外滚动页面，确认互不抢夺事件。
  - 点击图谱空白，确认选择/高亮清除；确认侧栏不再依赖单独的 `Clear Highlights` 按钮。
  - 横向拖动图谱和节点，确认位置连续、松手后稳定，无明显闪烁。
- **放行条件**：用户确认交互手感和原有图谱操作保持一致后进入任务 3。

### 任务 3：搜索结果选择与队列状态一致性

- **负责人**：搜索状态实现
- **问题**：`2.1` 选中结果不明显；`2.2` 队列项缺少状态标记/持久成功反馈；`2.3` 搜索变更后右侧详情与列表不同步。
- **实现边界**：复用现有选中态、下载队列和详情数据；统一状态来源，避免引入第二套缓存或改动 API。
- **自检与视觉检查**：切换结果、筛选和搜索词，确认列表选中项、右侧详情、图谱酶卡、下载队列使用同一实体和状态；加入/移除队列后刷新或重新搜索，确认反馈仍可见；确认无结果时不会显示上一次详情。
- **人工检查点 3**：
  - 点击不同类型的搜索结果，确认选中项有明确但克制的现有风格高亮，右侧详情立即对应。
  - 将条目加入/移出队列，确认列表、详情、图谱相关卡和下载队列的状态标记一致且成功状态可持续识别。
  - 修改搜索词和筛选条件，确认右侧详情不会停留在旧条目，空结果时显示正确空状态。
- **放行条件**：用户确认状态链路一致后进入任务 4。

### 任务 4：搜索侧栏、详情滚动与内容适配

- **负责人**：页面布局实现
- **问题**：`2.4` 详情内容滚轮滚动；`2.5` 重复 Clear filters；`2.6` Searching filters 侧栏滚动；`2.7` 统计文案对比度；`2.8` 长 SMILES 等字符串溢出。
- **实现边界**：保持现有搜索页三栏结构和密度；只调整滚动容器、重复入口、文本颜色、断行/横向溢出策略及对应响应式规则。
- **自检与视觉检查**：在长结果集、长字段和窄视口下检查；确认滚轮作用于当前悬停面板，页面不会被锁死；确认删除重复入口后仍有一个可达的清除筛选操作；长字符串不撑宽页面或覆盖邻接内容。
- **人工检查点 4**：
  - 在右侧详情面板和 Searching filters 侧栏内滚轮，确认面板独立滚动且页面整体仍可正常滚动。
  - 确认页面头部不再出现重复的 `Clear filters`，保留入口功能完整。
  - 确认 `Showing ... curated entries` 与背景有足够对比度。
  - 打开含长 SMILES/长标识符的条目，确认可读、可复制且不发生横向撑破或遮挡。
- **放行条件**：用户确认桌面、窄屏和长内容场景均无回归后进入任务 5。

### 任务 5：全量回归与交付记录

- **负责人**：主执行 / QA
- **范围**：仅回归第 1、2 大类涉及的页面和共享组件，不处理第 3、4 大类。
- **自检**：前端构建；前后端启动/健康检查；逐项复核 `1.1`–`1.8`、`2.1`–`2.8`；检查控制台错误、网络失败、响应式断点和键盘可达性；确认没有误改用户已有工作区文件。
- **人工检查点 5**：用户按最终清单走查星图、搜索、详情和下载队列核心流程，确认原功能与原设计风格保持不变。
- **交付条件**：所有检查点均通过，并在 AI 工作文档中记录最终结果、遗留风险（如有）和未处理范围。

## 4. 统一验收标准

- 原有导航、搜索、筛选、选中、详情、图谱拖拽/缩放、队列和下载流程仍可用。
- 不引入新的视觉主题、组件库或大范围布局重构。
- 桌面视口（建议 1440×900）与窄视口（建议 375×812）均无明显遮挡、溢出、跳动或不可达控件。
- 每项任务都完成“执行者自检/视觉检查 → 用户人工检查 → 记录结论”闭环。
